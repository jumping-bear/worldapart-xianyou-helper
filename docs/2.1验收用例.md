# 2.1 验收用例

> 配套《2.1支线与人物志模块优化方案.md》第六章验收清单与第七章痛点映射表。
> 用例编号与验收清单一一对应：QT=quest 模块，HC=hongchen 模块，RB=rolebook 模块，REG=通用回归，DOC=文档交付。
> 约定：所有用例在**各自 feature 分支**先自检，合并后在 `release/2.1` 集成分支再跑全量回归（REG 组）。

## 通用环境与约定

- **验收数据源**：以实际游戏目录（`config.json` 定位）为准，参照方案"附：关键数据源"各配置表。
- **快照生成**：`python meta_update.py --export-snapshots <游戏目录> . --only <key>`；前端查看用 `xianyou_assistant.py` 起预览或 `--once --no-browser --out-dir tmp/preview` 产出静态快照。
- **判定口径**：用例只验"可观察行为"（快照字段、UI 呈现、筛选结果、命令输出），不验代码实现方式；凡标"配置驱动"的用例，必须做"加一行数据看是否自动更新"的动作。
- **失败记录**：每条用例给出"通过 / 不通过 / 阻塞"，不通过时记录实际值 vs 预期值。

## 一、quest 模块（QT）

### QT-01 主干顺序边自动生成
- **前置**：quest build 已产出 `edges[]`。
- **步骤**：在任务树视图打开"筑基支线-纪小蝶-寻仙人"链，查看主干节点与连线。
- **预期**：存在顺序边 `70250→70251→70252→70253`，`kind=sequential`，与配置 `prev/next` 一致；无手写 id 痕迹（改动配置后边随之变化）。
- **对应痛点**：#3。

### QT-02 剑下抉择分叉 + 门槛标注
- **步骤**：查看 70253"剑下抉择"的下游分叉。
- **预期**：分出两条 `branch` 边——70254"出手相救"（无条件）与 70255"一旁静观"（标注"需灵机≥7"）；两条同属互斥组 `branch_key=p:c70250:70253`；门槛文字来自条件 alias，非硬编码。
- **对应痛点**：#2、#3。

### QT-03 汇合 + 互斥再分
- **步骤**：查看 70254/70255 下游汇合点及 70258 之后的分叉。
- **预期**：两路汇合到 70258"手札余话"；70258 再分 70259"一番劝言"与 70260"一试引气"，二者属互斥组 `p:c70250:70258`，树上有互斥/二选一标识。
- **对应痛点**：#3。

### QT-04 提交触发隐藏任务
- **步骤**：查看 70264"暂歇片刻"到 70266"未竟之约"的连线。
- **预期**：存在 `triggered` 边（事件=任务提交，来源 70263→70264 完成后触发）；目标 70266 标 `hidden=true` /"隐藏·列表不可见"。
- **对应痛点**：#1、#3、#5。

### QT-05 小蝶境界条件边（彩蛋）
- **步骤**：查看 70266"未竟之约"到 70267"小蝶近况"的连线与节点标记。
- **预期**：存在 `conditional` 边，标注"纪小蝶境界≥1"（来自 70267 `acq_cond`）；边/节点带彩蛋标记（egg）；前端默认不剧透后果。
- **对应痛点**：#1、#3。

> QT-01~QT-05 合并判定：5 类关系全部能由配置自动生成，即"任务树理清"达标。

### QT-06 触发条件三分类解析
- **步骤**：抽查任务的 `trigger_detail`，覆盖"任务提交""进入场景""接取条件满足"三类事件；重点看 70251/70252/70253（任务提交）与 70250（接取条件满足）。
- **预期**：每个任务标注由什么事件触发；不再出现因 `quests>1000` 启发式导致的误判（把非任务 id 当任务）。
- **对应痛点**：#3。

### QT-07 解锁条件完整树 + 混合逻辑标注
- **步骤**：查看 70266 与 70267 的 `acq_cond.tree`。
- **预期**：①70266 `mode=unknown` 明确显示"含混合逻辑（且/或嵌套），需人工确认括号语义"，不再静默判不了；②"非(持有/完成)"类 check 保留可读 kind，不降级为空；③70267"纪小蝶的境界≥1"以可读文字出现；④保留完整嵌套树而非只拍平。
- **对应痛点**：#1。

### QT-08 选项门槛 P0 提示（重点：无灰字选项）
- **步骤**：在 70253"剑下抉择"的分支卡片查看"一旁静观 / 暂且旁观"选项；再抽查 11235（体魄/神识≥3）、70130（欧冶青好感≥100）、70043（买下剑谱需灵石≥50）。
- **预期**：这些门槛以人话显示在分支卡片上；其中游戏内 `optionGreyText` 为空的（如 70253）在助手里有醒目提示；"灵机≥7""体魄≥5""好感≥100""灵石≥50""需某物品"等能正确翻译。
- **对应痛点**：#2。

### QT-09 选项门槛分级（防刷屏）
- **步骤**：查看 diagnostics 全量清单，统计分级。
- **预期**：P0（属性/好感/物品/门派，约 259 个）进"易踩坑"重点提示；善恶击杀类（141 个 `NPC_KILL_DEVOUR_*`）与随机事件类（56 个 `NPC_JEALOUS_*`）标为 P2，不在对话提示里逐个刷屏（交由人物志善恶模块承载）。
- **对应痛点**：#2。

### QT-10 隐藏任务统一标识
- **步骤**：查看全部 `hidden=true / trackOnAcq=false / trackOnProgress=false` 的任务（244 个）标签，并检查 70266/70267 在树中的说明。
- **预期**：统一显示"隐藏·列表不可见"标签；树里说明其触发条件；玩家不再把"隐藏但已触发"误判成"没触发"。
- **对应痛点**：#1、#5。

### QT-11 彩蛋折叠展示
- **步骤**：打开 70266"未竟之约"详情，先在任务树/列表态查看，再展开详情"隐藏结局"区块。
- **预期**：默认态不剧透（diagnostics 中 `egg=true`）；主动展开后才显示"不给洗髓灵液(100100)就突破结丹会导致小蝶死亡"的后果与关键道具。
- **对应痛点**：#1。

### QT-12 任务树视图与易踩坑筛选 + 改动范围
- **步骤**：①使用 quest 视图的"任务树视图"与"易踩坑"筛选区；②检查本次 quest 改动文件清单。
- **预期**：①任务树可交互（点节点看条件/门槛/隐藏），易踩坑能筛出含隐藏/门槛/彩蛋的任务；②改动仅限 `app/modules/quest/` 内，未修改任何共享文件（`app/modules/__init__.py`、`app/tablekit.py`、`meta_update.py`、`app/render.py` 等）。
- **对应痛点**：#3、#8。

## 二、hongchen 红尘模块（HC）

### HC-01 250 任务全收录
- **前置**：quest 模块 `TABLES` 已声明 `tbquesttype`，`build.py` 已改为动态读取类型。
- **步骤**：刷新快照后统计 type=5 的 `hongchen` 集合条数。
- **预期**：从当前 0 条变为 250 条；`build.py` 中不存在写死的 `quest_type == 2 or "支线" in label` 判定；快照中同时保留 type=2 的 `quests`（254 条）不丢失。
- **对应痛点**：#4。

### HC-02 六条角色线齐全
- **步骤**：按 `taskGroup` 聚合 `hongchen`，统计每条线任务数。
- **预期**：恰好 6 条线，数量分别为 芊儿 41 / 念乔 64 / 沈桐桐 62 / 云嫣 21 / 赤遥 22 / 慕云栖 40（合计 250），每条线成一棵独立任务树。
- **对应痛点**：#4。

### HC-03 任务树与分支门槛显示
- **步骤**：逐线打开任务树，查看分支选项门槛。
- **预期**：任务树结构清晰（主干/分叉/汇合/互斥）；分支门槛可见，如 80015"强硬护她"需体魄≥3 能显示。
- **对应痛点**：#4、#8。

### HC-04 传音接取条件提示
- **步骤**：查看 80079"桐花传音"等传音接取节点。
- **预期**：`acqCond` 指向的条件（传音接取）在助手里有提示，玩家知道该节点如何触发。
- **对应痛点**：#4。

### HC-05 界面精致度
- **步骤**：打开红尘板块，逐线检查视觉与交互。
- **预期**：每条线以"角色头像(portraitIcon，取自 tbnpcbasecfg) + 名称"作卡片头；节点用带情绪色彩的分支卡片，选项分支用不同颜色区分；支持折叠/展开与进度高亮；整体明显区别于普通支线样式。
- **对应痛点**：#4、#8。

### HC-06 数据驱动（新增任务自动出现）
- **步骤**：往配置表新增一条 type=5 任务（虚构 id 与 taskGroup=某角色线），刷新快照后查看红尘板块。
- **预期**：新任务自动出现在对应角色线树中，前端代码零改动。
- **对应痛点**：#9。

## 三、rolebook 人物志模块（RB）

### RB-01 NPC 全息 11 维度齐全
- **步骤**：打开任一有完整配置的 NPC（如纪小蝶 100121）详情卡。
- **预期**：11 个维度全部呈现且数值/标签来自对应配置表：
  1. 基础（名字/头像/性别/年龄/种族/门派/境界/元素）
  2. 性格（propPersonality + tbnpcpersonality 14 种 + 悬浮说明）
  3. 善恶（propEvil + tbnpcevildesc / tbalignmenttitle，色带+称号）
  4. 声望（propRepute + tbnpcreputedesc 称号）
  5. 魅力（propCharm + tbnpccharmdesc 6 档评级）
  6. 悟性（initial_wisdom + tbnpcwisdomtitle 等级）
  7. 亲密（tbnpcintimacy 8 档 + 存档好感度进度）
  8. 资质（talent_slots + tbnpctalent 可结道侣条件）
  9. 能力标记（can_be_dao_companion / can_spar / can_kill / can_steal / is_merchant 图标）
  10. 互动（tbnpcchatbubble / tbnpctopicchat / tbnpcpersuadetopic 可聊话题/说服入口）
  11. 专属内容（红尘线 type=5 / 留影 tbmemoriaentry / 剧情 tbnpcepisode 入口）
- **对应痛点**：#7。

### RB-02 魔修"安全目标"一键筛选
- **步骤**：使用"安全目标"筛选，并导出结果 NPC id 集合；用脚本从 `tbnpcbasecfg` 计算 `propEvil<0 且 can_kill` 的集合。
- **预期**：两集合完全相等（不多不少）；筛选结果可点击进详情。
- **对应痛点**：#6。

### RB-03 攻击风险提示
- **步骤**：选中一个 NPC，查看"攻击此人"风险区。
- **预期**：显示 善值+X / 恶值-Y / 城镇声望-Z / 追杀概率N%，数值与 `tbalignmentattackgain`、`tbevilattackprobability` 一致；含称号与恶人描述（tbnpcevildesc）。
- **对应痛点**：#6。

### RB-04 界面布局与交互流畅度
- **步骤**：卡片墙滚动→点开头像进详情抽屉→用多维筛选/排序→关闭抽屉返回。
- **预期**：头像网格（1313 个有头像）加载流畅；详情抽屉展开/收起正常；多维筛选（善恶/境界/门派/性格/种族/可结道侣/有红尘线/可否击杀）与排序可用；善恶中轴色带、亲密进度条、悟性/魅力星级可视化呈现。
- **对应痛点**：#7、#8。

### RB-05 关联跳转不 import 模块
- **步骤**：从某 NPC 卡片的红尘线/留影/天赋槽入口点击跳转；检查 rolebook 源码 import。
- **预期**：跳转只传 id 到对应模块详情；rolebook 的 `__init__.py/build.py/scan.py/view.js` 不 import quest/memoria 等其它模块，需要的表自己在 `TABLES` 声明并从 `tables` 取。
- **对应痛点**：#8、#9。

### RB-06 模块加载隔离
- **步骤**：临时破坏 rolebook 的快照/模块（如在副本工作区移除其 SNAPSHOT），运行助手。
- **预期**：其余模块正常加载；出现 rolebook 自身的告警但无「功能模块加载失败」连带崩溃；恢复后正常。
- **对应痛点**：#9。

## 四、通用回归（REG）

### REG-01 游戏更新不改代码（配置驱动总验）
- **步骤**：分别在配置表新增 ①一条任务（type=2/5）②一条条件表达式（tbconditionexpr）③一个 NPC（tbnpcbasecfg）④一条善恶规则行；刷新快照后查看对应 UI。
- **预期**：四类数据均自动进快照与 UI；全程不改任何 .py/.js/.css；quest 任务树、诊断提示、人物志卡片随之更新。
- **对应痛点**：#9。

### REG-02 打包边界
- **步骤**：执行 `python -m tools.packaging --check`，观察打包是否访问游戏目录。
- **预期**：打包不访问游戏目录、不重新解包，只消费已提交快照；发布时由脚本把根目录快照同步进 `仙友助手/`。
- **对应痛点**：#9。

### REG-03 失败兜底
- **步骤**：制造存档/配置解析失败（损坏表或缺失表）后运行助手。
- **预期**：回退内置 SNAPSHOT，助手不崩；界面显示兜底数据而非报错页。
- **对应痛点**：#9。
