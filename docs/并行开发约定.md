# 并行开发约定

本文件是 `app/modules/<key>/` 插件式模块的协作约定，配套方案见
`2026-11-16/parallel-dev-audit/outputs/装配层与发布层解耦方案设计.md`。

## 一、模块最小形态

新增功能只新增 `app/modules/<key>/` 目录与自己的快照文件，**不修改任何既有共享文件**。

```
app/modules/<key>/
  __init__.py    必需：KEY、LABEL；建议显式 ORDER、SCHEMA、TABLES、SNAPSHOT
  build.py       可选：build(tables) -> dict，把配置表压成模块快照
  scan.py        必需：scan(obj, meta, state) -> rows（可选 meta/prepare/post/enrich/score/summary/empty/builtin_ok）
  view.js        可选：window.PROGRESS_VIEWS[key] = function(DATA){...}，整体用 IIFE 包裹
  view.css       可选：只写本模块自己的选择器，全局通用样式不要往这里放
```

`__init__.py` 示例：

```python
KEY, LABEL = "memoria", "留影石"
ORDER, SELECT, SCHEMA = 80, "latest", 1
SNAPSHOT = "memoria_meta.json"
TABLES = frozenset({"tbmemoriaentry", "tbmemoriabondtype"})
```

- `SCHEMA` 是该模块**独享**的缓存版本，新模块从 `1` 起；改数据结构时只递增自己的值。
- `SNAPSHOT` 与 `EXTRA_SNAPSHOTS` 的文件名必须全局唯一，且文件要提交入库。
- 有 `build` 就必须有 `SNAPSHOT`；没有 `build` 就必须有已提交的快照文件。
- 模块之间禁止互相 import；需要奇遇/物品等其它模块的数据时，从 `tables` 里自己取对应配置表，
  或在 `TABLES` 里声明该表，不要 import 别的模块。

契约校验由 `app/modules/__init__.py` 在发现阶段完成：`F*` 为阻断级、`W*` 为告警级，
详见方案文档 3.3。运行期只告警，发布期（`python -m tools.packaging --check`）严格阻断。

## 二、共享文件的写者

| 文件 | 唯一负责人 |
|---|---|
| `app/modules/__init__.py`、`app/tablekit.py`、`meta_update.py`、`app/render.py` | 装配负责人 |
| `TouchProgress.spec`、`tools/packaging.py` | 装配负责人 |
| `app/version.py`、`release/`、`tools/release.py` | 发布负责人 |
| `仙友助手/`、`workshop_release/` | 发布负责人 |

其他任务只提需求，不直接修改上表文件；需要新增解析工具函数时，向装配负责人提出，
由其在 `app/tablekit.py` 追加（只增不改）。

## 三、并行与提交

1. 每个并行任务用独立 worktree：`git worktree add ../xy-<任务> -b feature/<任务> main`。
2. 开工前 `main` 必须是可打包基线（`python -m tools.packaging --check` 通过）。
3. 合并顺序固定：模块代码 → 快照 → 版本与发布物料；后两步由发布负责人单人执行。
4. 合并前 `git rebase main`，并在自己分支跑一次：
   `python xianyou_assistant.py --once --no-browser --out-dir tmp/preview`，确认无「功能模块加载失败」。

## 四、快照与发布边界

- 快照是**源文件**，必须提交；刷新快照是独立动作：
  `python meta_update.py --export-snapshots <游戏目录> . --only <key>`
- 主快照统一命名 `<key>_meta.json`，`.gitignore` 已用 `!/*_meta.json` 自动放行，不需要改忽略规则；
  若模块有额外快照（`EXTRA_SNAPSHOTS`）且文件名不是 `*_meta.json`，由装配负责人在 `.gitignore` 追加一行。
- 打包**不访问游戏目录**、不重新解包，只消费已提交快照；发布时由脚本把根目录快照同步进 `仙友助手/`。
- 根目录 `仙友助手.html` / `仙友助手版本.js` 只是开发预览，不进安装包；
  发布产物由 `python tools/release.py` 直接写入 `仙友助手/`。
- 版本号唯一来源是 `app/version.py`，其它位置由发布脚本生成或校验，不要手抄。

## 五、发布前检查

```
python -m tools.packaging --check     # 模块契约 + 打包 datas 预演
python tools/release.py --check       # 版本一致性 / 工坊物料 / vdf 路径
```

任一项失败都不发布；上传仍由人工执行 `workshop_release/upload_to_workshop.bat`。
