# 模块数据备忘

游戏侧实测结论，按模块归档。每条标注日期，游戏版本更新后需重新验证。
通用取数方法见《数据来源与反编译.md》。

## 炼丹（2026-11-27）

- 丹方主效果 `main_effects[].type` 是 **1..15 裸编号**，与 `tbpilleffect` 的 id（11/21/31…）不是同一套；
  配置里未找到可靠名称表（`PillCategory` 只有 0..3）。**禁止编造功效分类名**，只能靠描述文本关键词匹配。
- `pill_map.json` 中丹方的 `fx` 字段由 `build_pill_map` 从 effects 汇总，供「按功效反查」使用。

## 奇遇（2026-11-26 ~ 11-27）

- 数据源是 `tbrandomeventending` 里有结局记录的事件，数量随版本变化；`tbquest type=3` 还包含宗门任务，不能按 type=3 全集分析页面。
- 完成判定需额外读回忆收录（`playerModel.memoria.unlocked`）：可重复奇遇结算被重置时，只要回忆已收录即算达成。
- 结算记录可能挂在**非自身 id 的合成键**下，需按结局 id 反查所属奇遇再合并奖励，否则会漏。
- 多分支可选奇遇（如赤瑶红尘）按每个分支自身的接取流水生成路线；未选择的分支不计入完成进度分母。
- 不同结局的获取条件必须**从剧情树反推**（只有所有走法都带条件才算硬门槛），并直接写在结局旁，不能只藏进「完整对话分支」折叠区。
- 父子关系仅按已有 `parent` 字段与「母奇遇名·分支名」命名规则判定；无法确定的保持平铺。
- 宗门限制有三层：场景交互图标解锁条件、交互动作开放条件、任务接取条件；漏任一层会把「需入宗门」误判为「已开启」。
- 前置解析链路：`tbquest.triggerExpr/acqCondition` → `tbconditionexpr`（先展开 alias）→ 前置任务接取入口（`tbdialogue.optionExpr` / `tbinteractaction+ui` / `tbgameactionflow`）→ 存档 `questComponent.quests[id].state` 验证。
- 前置必须展示「获取方式」（对话选哪项 / 场景交互点 / 流程），不能只写任务名；同系列 hidden 记账任务（温养/已领等）不算玩家前置。
- 奖励展示阈值：品质 ≥3（紫/金/红）且未拥有；最多展示 3 个，超出显示 +N。

## 红尘（2026-11-27）

- 条件别名不能按名字猜：`SIDE_ZHUJI_<任务>_O<N>` 实际是**选项的属性门槛**（辩道/神识/体魄等级），必须读 `tbconditionexpr` 的真实表达式。
- 「修炼阶段达到」的参数是**阶段 id**（2=炼气中期），要按 `phase_order` 比较，不能当境界 id（2=筑基期）或直接和层号比大小。
- 按前置深度算的「环」对玩家无意义，导航必须按真实前置关系拆成独立故事线。
- 开启条件统一分五类自动推导：已提交前置主线 / 境界门槛 / 接取条件境界 / 对话接取 / 无前置。
- 交互点仅当接取的是链首任务（无前置、非任务提交触发）时，才能作为剧情线起点与线名。
- 角色线数量随版本变（2026-11-27 这版 7 位：云嫣/念乔/慕云栖/沈桐桐/芊儿/赤遥 + 新增墨巧巧），文案不得写死段数。
- 红尘类型里混有无 `taskGroup` 的隐藏引导任务（如 `81011`「乌茉来讯」：乌茉是青岚洲客栈凡人掌柜，
  有天赋槽与闺房，但**没有红尘支线**）。这类任务不能按分组建成角色卡，否则会凭空多出一条「女主」线。
- 改红尘构建逻辑后必须递增 `app/modules/hongchen/__init__.py` 的 `SCHEMA`，否则运行时缓存指纹不变、旧数据继续生效。

## 仙居楼（2026-11-27）

- 每位仙友 3 个部位 × 每部位 6 段 = **18 段**；`total>=18` 才算完成 1 位。
- 十八摸成就按**曾经获得过**的段累计：合并同一角色所有槽位，每个部位取并集。
  只取最新档会看起来不更新，只取单份最高档会跨时间线丢段。
- 合并范围限定当前/固定角色，不能混入别的角色。

## 璞石（2026-11-27）

- 品质编号 1 白 … 5 橙，与物品 0 起编号是两套，见《数据来源与反编译.md》第二节。
- 专属璞石靠 `tbgamblestoneembryoexchangeband.exclusive_stone_item_id` 指回物品，
  该 id 不在模板/器胚引用集合里，必须显式并入 `items`，否则页面只能回退「未识别璞石」。
- `playerModel.combat.base_attrs`：`200` = 精力（当前），`201` = 精力上限（**基础值**）。
  当前值可大于基础上限（天赋/装备加成不进 base），所以不能直接写成 `当前/上限`。

## 探索（2026-11-27）

- 五项探索属性经验来自 NPC 每月特殊互动入口的奖励掉落（物品 1001~1005），属性 id、名称、顺序都从
  `tbinteractattribute` 取，不从存档或页面反推。
- 每个 NPC 每月最多 1 个特殊入口；入口按自身 `maxSuccessCount` 计数，完成后本月清空。
- `SPAR_MONTHLY_LIMIT=3` 与 `playerModel.spar_monthly_count` 在当前版本托管代码里只有
  `EnsureSparMonthlyCount` / `ResetSparMonthlyCount`，没有读取点，不能据此显示「剩余切磋次数」或限制推荐数量。
- 普通菜单切磋的 `tbnpcsparkillbattleconfig` 只有亲密度与击杀关系字段，没有属性经验掉落；体魄经验以特殊入口奖励为准。
- 委托/宗门任务里的「切磋 / 疏经导脉」目标 NPC 从任务目标流参数取；任务动作与本月入口是否重合要分别展示。
- 接取地点取 `tbcommissionforcetaskrefresh.entry_scene_id/entry_npc_id`，目标地点取 `tbquest` 目标描述的高亮地点；
  两者可能不同，页面必须分别写清「接取」和「目标」，不能只写任务名。
- 任务可做性由 `QuestNpcSpecialStateResource` 决定：`IsTaskSpecialStateType` 只对 2（说服）/ 3（疏经导脉）开启，
  接取后任务作用域内为目标 NPC 获取临时特殊入口，结束时释放；切磋不在其中，靠 NPC 菜单切磋即可完成。
  所以不能把「本月没抽到入口」当成委托做不了。

## 境界修为（2026-11-27）

- `tbsourceroute.trackType=2` 的 `trackParam` 是 `tbpillrecipe.id`，必须查丹方名（`name`）再展示；
  直接拼编号会踩「不得暴露内部编号」。查不到时降级为「炼丹配方」。
- 妖兽刷新只需在摘要行回答「有没有刷」：`已刷新 N 支` + 下一轮日期；明细展开再看哪张图，否则妖兽块会吃掉整屏。

## 附：存档读取与扫描（工具侧契约）

- 模块声明 `SELECT="merge"`：扫描该角色全部自动/手动槽位，取字段并集（曾经获得过的内容不丢）。
- 模块声明 `SELECT="best"`：取进度最高的一份。
- 未声明时只读各角色最新存档，保证解析速度。
- 多槽位模块需按「文件路径 + 修改时间 + 大小」缓存，仅当文件实际变更才重新解包。
- 存档扫描只检查文件时间戳；轮询间隔 2.5 秒，「立即同步」1 秒冷却。
