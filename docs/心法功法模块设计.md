# 心法与功法模块设计（v3 实现稿）

> 在 v2 评审稿基础上按**实际配置表与 29 份存档**校正字段、状态模型与分阶段范围。
> 本稿对应分支 `feature/1.9-xinfa-gongfa`，M1（骨架/快照/四页签）+ M2（体检规则）已完成，
> M3（方案卡、功法对比、流派引擎）保留设计不提前实现。

## 一、模块定位

回答三个问题，不做事典：

1. 现在装的心法和功法有没有问题？
2. 没运转的功法、没参悟的卷册、没装的共鸣，缺什么、去哪拿？
3. 下一条最小提升路线是什么？（M3）

只提示「可确认」的问题；有争议的机制写成「待复核」，不写成结论。
不写「推荐指数」，不推断功法升阶关系，不把道侣写成共鸣解锁条件。

## 二、数据契约（v3 修正）

### 2.1 存档

所有战斗字段在 `save.playerModel.combat`，不是顶层 `combat`：

| 用途 | 路径 | v3 修正 |
|---|---|---|
| 已装心法 | `playerModel.combat.core_passive_slots` | 键为 **1 起始**的槽位号，值 `{slot_index, core_passive_id}`；容量 = 字典长度，空槽的 `core_passive_id` 为 0 |
| 每本心法的功法预设 | `playerModel.combat.core_passive_skill_configs` | **只代表该心法自己的 4 格预设，不代表正在运转**；必须用已装心法过滤 |
| 已学心法 | `learned_core_passives` | int 列表 |
| 已学功法 | `learned_skills` | `{skill_id: level}`，键可能是 int，统一 `int()` |
| 共鸣槽 | `support_skill_slots` | 旧存档可能为 `{}`；此时容量记「未记录」，**不要当成 0 槽**，也不要触发 R10 |
| 已学共鸣 | `learned_support_skills` | 同上 |
| 共鸣境界 | `resonance_skill_realms` | 旧存档可能缺失；缺失时显示「未记录（旧存档）」 |
| 当前境界层 | `playerModel.combat.cultivate_layer_id` | 用 `tbcultivatelayer.phase` → `tbcultivaterealm.phases` 翻译成境界 |
| 门派 / 灵根 | `playerModel.current_sect_id`、`talent_path.spirit_root_point_map` | 灵根键为五行 id |
| 背包 | `playerModel.bag.items` | 用递归取含 `item_id` 的节点，再筛 `learn_target_type` |
| 双修统计 | `npcs[npcId].dual_cultivate_success_statistics` | 键是 `npcCfgId` → `{dual_cultivate_id: 次数}`，仅作剧情门控，不是道侣判定 |

背包卷册判定：`learn_target_type` 1=功法、2=心法；`comprehend_value` 对比
`tbminigamelearngongfa.comprehend_value_limit`，无记录时显示「未记录」。

## 三、快照结构

`martial_meta.json`（约 72 KB）：

```text
schema, elements{0..5}, realms{}, phases{层起点:境界}, tier_phase{境界:起始层},
layers{层: {phase, layer}}, sects[], intimacy[],
core_passives[], arts[], resonance[],
names{npc,item}, stats{core,arts,resonance,books,excluded[]}, warnings[]
```

- `core_passives[]`：id/name/element/tier/sect/slots/book/price/stack/unit/init[]/tiers[]/
  teach/comprehend/desc/shops[]
- `arts[]`：id/name/element/tier/sect/mystery/book/price/teach/comprehend/desc/costs/grade/shops[]
- `resonance[]`：id/name/element/tier/desc/npc/npc_name/unlock_layer/source
- `unlock_layer` 由 119x 词条的 `skill_tier` 推境界起始层（筑基 = 21），不是配置里的独立字段
- 视图不写死门派、元素、境界、档位、槽位、价格；全部从快照取

## 四、状态模型（v3 改为正交）

v2 用一条「状态优先级」混合了「有没有装」和「从哪拿」，会出现「已运转」和「货架」互斥。
v3 拆成两个维度：

**状态**：`已运转` / `已学会未运转` / `卷册在包` / `尚未获得`（心法另有 `特殊`）
**来源**：`货架` / `可请教` / `卷册` / `入门自带` / `未开放` / `特殊`

- 「已运转」只统计**已装心法**的 `core_passive_skill_configs` 非 0 功法
- 「卷册在包」= 背包里有该目标且尚未学会
- 心法「特殊」= 万法随心这类无门派、无卷册的通用心法
- 来源展示所有可用路线，卡片正文同时列出卷册、货架、请教、入门自带，不只显示一个

## 五、体检规则（M2 已实现）

| 规则 | 级别 | 条件 | 目标 |
|---|---|---|---|
| R01 | 高 | 已装心法 < 槽位容量 | 心法槽 |
| R02 | 中 | 已学心法未装槽 | 心法 |
| R03 | 中 | 已装心法的功法格有空位 | 心法 |
| R04 | 中 | 已学功法未出现在已装心法的预设里 | 功法 |
| R05 | 高 | 已运转功法元素 ≠ 心法元素（通用心法跳过） | 功法 |
| R06 | 高 | 已运转功法境界 ≠ 心法境界 | 功法 |
| R07 | 低 | 同元素心法装了多本（待复核） | 心法槽 |
| R08 | 中 | 已装心法有同名更高境界且已学 | 心法 |
| R09 | 低 | 背包有未参悟卷册 | 卷册 |
| R10 | 中 | 共鸣槽未满，或已学共鸣未装；槽位未记录时不触发 | 共鸣 |
| R11 | 提示 | 功法/共鸣没有任何可用来源 | 功法/共鸣 |
| R12 | 告警 | 配置未识别、缺表、解析失败（排除以「说明：」开头的已知缺口） | 数据说明 |

每条结论都带 `target {kind,id}`，点击可跳到对应页签、卡片或区块。

## 六、四页签

- **总览**：心法槽 / 已运转功法 / 共鸣 / 体检数；门派、境界、五行灵根；心法槽网格（4 个功法格）；
  共鸣槽；体检结论；未参悟卷册；数据说明
- **心法**：门派/元素/境界/状态/来源筛选；卡片含真意档位表、初始功法、卷册价、请教、参悟、货架；
  同名不同境界只做原文对照
- **功法**：门派/元素/境界/秘传/状态/来源筛选；行展开显示效果、消耗、卷册、货架、请教、入门自带

旧存档 `support_skill_slots={}` 时显示「存档未记录共鸣槽（旧存档）」，不渲染 0 格。
