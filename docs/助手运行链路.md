# 助手运行链路（从游戏启动到 F3 浮窗）

> 这份文档回答一个问题：**按 F3 时，到底是谁、哪份文件、在什么时机跑起来的？**
> 每一环都标了"源码位置 / 本机证据"，便于对照排查。

---

## 一、完整链路

```
Steam 启动 WorldApart.exe
   │
   ├─① Doorstop 在 Unity 启动前注入
   │     winhttp.dll + doorstop_config.ini → dotnet\coreclr.dll
   │     （BepInEx 6 带进来的 .NET 6 运行时，进程里看到的就是它）
   │
   ├─② BepInEx 加载插件
   │     BepInEx\core\BepInEx.Unity.IL2CPP.dll → BepInEx\plugins\SaveDecryptProbe\SaveDecryptProbe.dll
   │     证据：BepInEx\LogOutput.log「Loading [SaveDecryptProbe 1.5.0]」
   │
   ├─③ 插件初始化（Plugin.Load）
   │     ├─ 建 BepInEx\decrypted 目录
   │     ├─ AddComponent<Boot>()        → 每帧 Update
   │     ├─ Application.runInBackground = true      ← 独占全屏下不合法
   │     ├─ Updater.Run()              → 比对工坊 version.json，自动更新
   │     └─ StartAssistant()           → 拉起覆盖窗口（见 ④）
   │
   ├─④ 拉起覆盖窗口进程
   │     Plugin.cs:51
   │     "仙友助手.exe --overlay --silent --parent-pid <游戏PID>"
   │     exe 位置：BepInEx\仙友助手\仙友助手.exe（不存在时退回游戏根目录）
   │     证据：LogOutput.log「[assistant] 已启动覆盖窗口：...」
   │
   ├─⑤ 一次性包自解压
   │     PyInstaller one-file → %TEMP%\_MEIxxxxxx\
   │     （解压本身要几百毫秒，是每场游戏启动时的第一个"卡点"候选）
   │
   ├─⑥ 覆盖模式入口
   │     xianyou_assistant.py main() 识别 --overlay：
   │     ├─ OVERLAY_MODE = True
   │     ├─ 起 watch_parent(game pid) 线程：游戏退出 → os._exit(0)
   │     ├─ 起 watch() 后台线程：每 2.5 秒检查存档 → render() → 重写 仙友助手.html
   │     ├─ 写崩溃标记 %TEMP%\xianyou_overlay_running.flag     ← 在 webview.start() 之前
   │     └─ run_overlay(html, start_hidden, hotkey, compat)
   │
   ├─⑦ WebView2 浮窗
   │     pywebview(gui=edgechromium) → msedgewebview2.exe 内容进程
   │     ├─ 无边框 + 置顶 + WS_EX_NOACTIVATE（不抢焦点）
   │     ├─ Hotkey 线程 RegisterHotKey(F3)   ← 无修饰键，全局独占
   │     ├─ 页面 JSON 接口：hide / activate / drag_* / set_size / sync / state / quit
   │     └─ 页面未生成时先显示 loading 页，_await_page 每秒轮询，就绪后 load_url
   │
   ├─⑧ 玩家按 F3
   │     WM_HOTKEY → Controller.toggle() → ShowWindow(SW_SHOWNOACTIVATE) + SetWindowPos(TOPMOST)
   │     独占全屏下这一步会触发一次桌面前台/合成层切换
   │
   ├─⑨ 插件侧存档导出（与 ⑥⑦ 并行）
   │     Boot.Update 每 0.25 秒看 _refresh.flag，每 5 秒扫一次存档
   │     发现新存档 → DecryptOrPassThrough（il2cpp 静态方法）→ 写 decrypted\*.bin
   │     证据：decrypted\_status.txt「lastSync=...」
   │
   ├─⑩ 游戏退出
   │     OnApplicationQuit → StopAssistant() → Assistant.Kill()
   │     watch_parent 也检测到父进程退出 → os._exit(0)
   │     WebView2 子进程、崩溃标记文件都不会被清理
   │
   └─⑪ 自动更新（下次启动）
         Updater.SyncExe：Kill 所有同名进程 → 覆盖 exe
         Updater.SyncPluginDll：落 .pending → 生成 _update.cmd → 游戏退出后替换
```

## 二、三个关键事实（容易踩坑）

### 1. 游戏里跑的永远是"游戏目录下的那一份"

`install.ps1:269-278` 把安装包里的 `仙友助手.exe` + `config.json` + `version.json`
复制到 `游戏目录\BepInEx\仙友助手\`；插件只从这三个候选位置找 exe：

```csharp
Path.Combine(BepInEx.Paths.BepInExRootPath, "仙友助手", name)   // ← 实际命中
Path.Combine(BepInEx.Paths.GameRootPath, "仙友助手", name)
Path.Combine(BepInEx.Paths.GameRootPath, name)
```

**仓库里的 `仙友助手\仙友助手.exe` 只是发布源**，不会直接被游戏使用；
游戏用的是"上传到工坊 → Steam 下载 → 一键安装复制过去"的那一份。

### 2. 发布链路只有一条

```
tools/release.py release()
  ├─ generate_pages(仙友助手/)      生成页面
  ├─ build_exe()
  │    PyInstaller TouchProgress.spec → dist\staging\仙友助手.exe
  │    copy → 仙友助手\仙友助手.exe                      ← 这是发布的唯一来源
  ├─ write_version_file()            写 version.json（含 exe 大小与 SHA-256）
  └─ generate_vdf()                  写 workshop_release\workshop.vdf（contentfolder 指向 仙友助手\）
        ↓
workshop_release\upload_to_workshop.bat
        ├─ steamcmd +login +workshop_build_item workshop.vdf
        ↓
Steam 工坊 item 3839624741
        ↓
玩家订阅 → Steam 下载到 steamapps\workshop\content\4209920\3839624741\
        ↓
运行该目录的「一键安装.bat」（install.ps1）
        ↓
复制到 游戏目录\BepInEx\仙友助手\仙友助手.exe   ← 游戏实际运行
        ↓
之后由插件 Updater 按 version.json 自动同步
```

### 3. 当前线上版本与本机安装的是同一份

| 文件 | 大小 | SHA-256 |
| --- | --- | --- |
| `仙友助手\仙友助手.exe`（仓库 11-22 01:04） | 27683905 | `6463B896…C556BC` |
| `工坊\3839624741\仙友助手.exe`（11-21 23:54） | 27684703 | `08578371…5D507C3` |
| `游戏\BepInEx\仙友助手\仙友助手.exe` | 27684703 | `08578371…5D507C3` |

**游戏里跑的就是工坊这一份**（`version.json` 里 `exe_size` / `exe_sha256` 与它一致，插件也认为"已是最新 v2.4.0"）。
而仓库里 01:04 又打了一次包但**没有上传**（steamcmd 最后日志停在 11-21 23:53），所以两者不同——这属于正常状态，不用管。

## 三、时序耦合：为什么"卡死"总像是发生在某个时机

| 时机 | 同时发生的事 |
| --- | --- |
| 游戏启动后 ~30 秒 | ⑤ 解包 → ⑥ 写崩溃标记 → ⑦ WebView2 起内容进程 → watch() 首次 render（20 个模块、读 20 多份 4.8MB 存档、生成 9.6MB HTML）→ ⑨ 插件首次导出所有存档副本 |
| 每 5 秒 | ⑨ 插件扫存档；有变化就解密 + 写 `.bin`（主线程调用 il2cpp） |
| 存档后 ~2.5 秒 | ⑥ 助手侧 stat 到新 `.bin` → render → 重写 `仙友助手.html` → ⑦ WebView2 reload 整页（若浮窗可见） |
| 每按一次 F3 | ⑧ ShowWindow + TOPMOST + 合成层切换；页面 focus/visibility 事件触发 `PROGRESS_CHECK_FAST` |
| 每次点浮窗输入框 | `activate()` 解除 NOACTIVATE → 抢前台 |

**"F3 + 自动存档 + 同步"三者撞在一起**时，上表第 3、4 行会叠在同一秒内。

## 五、已知的"源码 vs 产物"风险

**`仙友助手.exe` 里查不到当前源码的覆盖模式代码。**

- `dist\staging`、`dist`、`仙友助手\` 三份 exe（含 11-21 23:54 上传的那份）里，
  能搜到 PyInstaller 归档的模块名 `app.overlay`，**但搜不到** `run_overlay` /
  `RegisterHotKey` / `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` / `_await_page` /
  `xianyou_overlay_running` 这些符号。
- 这**不代表覆盖模式不可用**（F3 实际能呼出），只说明**打进 exe 的 `app/overlay.py`
  和仓库当前文件不是同一版**，或者被 PyInstaller 以另一种方式编码了。
- 影响：**任何"源码里能看到因此线上也会发生"的推断都不可靠。**

建议在 `tools/release.py` 的 `build_exe()` 里加一步产物核对：打包后扫描 exe，
把命中的关键符号和 `app/*.py` 的哈希写进 `version.json`，让"源码与产物不一致"
在发布前就暴露，而不是等到出事故才靠人工比对。
